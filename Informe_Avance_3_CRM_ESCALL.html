1. INTRODUCCIÓN

El proyecto CRM ESCALL Perú apoya la gestión de cartera, clientes, cuentas, gestiones de cobranza, pagos y promesas de pago de ESCALL Perú S.A.C. La solución combina un frontend Angular, una API REST Spring Boot y persistencia MySQL.

Este documento corresponde al Avance 3. El Avance 1 definió el dominio y el prototipo; el Avance 2 desarrolló el backend con JPA/MySQL, consultas, seguridad y pruebas. El Avance 3 incorpora Angular y verifica el consumo REST, login JWT, operaciones protegidas y persistencia real.

2. PROBLEMA, REQUERIMIENTOS Y CONTINUIDAD

El problema es la gestión dispersa de la cartera y las gestiones de cobranza. Se requieren consulta organizada, navegación por perfiles, registro de gestiones y pagos, autorización por rol y datos conservados en MySQL.

3. DESCRIPCIÓN DE LA SOLUCIÓN INTEGRADA

Flujo operativo: Usuario → Angular → servicio/HttpClient → endpoint REST → Controller → Service → Repository JPA → MySQL. Angular trata la respuesta HTTP o DTO y actualiza la interfaz.

  • Angular presenta la interfaz, navegación y validaciones.
  • HttpClient realiza peticiones y el interceptor agrega Bearer.
  • Spring Boot expone API REST y aplica seguridad y reglas.
  • JPA/Hibernate traduce entidades a operaciones relacionales.
  • MySQL conserva clientes, cuentas, gestiones, pagos y usuarios.

5. ARQUITECTURA Y ESTRUCTURA FULL STACK

Arquitectura: Navegador → Router/Componentes Angular → Servicios → HttpClient/Interceptor → Spring Security → REST Controller → Service → JPA Repository → MySQL.

Frontend: componentes standalone; rutas en app.routes.ts; app.config.ts configura router y HttpClient; core contiene servicios, guardas, interceptor y modelos; pages contiene las pantallas reales.

Backend: Controller recibe HTTP; Service contiene lógica y transacciones; Repository usa Spring Data JPA; Entity representa tablas; DTO define contratos JSON; excepcion centraliza errores.

7. INTEGRACIÓN ANGULAR–SPRING BOOT

API_URL está centralizada en core/api.config.ts y apunta a http://localhost:8080/api. app.config.ts registra provideHttpClient(withInterceptors(...)).

Trazabilidad GET público: ConexionPage → PublicApiService.obtenerSaludo() → HttpClient.get → PublicController → texto 200 → suscripción RxJS → texto visible.

CORS: permite localhost/127.0.0.1:4200, métodos GET/POST/PUT/PATCH/DELETE y cabeceras Authorization/Content-Type.

JWT: AuthService obtiene el token, lo guarda en sessionStorage y valida vigencia; authInterceptor agrega Authorization: Bearer. Ante 401 limpia sesión y vuelve a /login.

8. INTERFAZ Y FUNCIONALIDADES DEL FRONTEND

  • /conexion muestra el GET público real.
  • /login autentica usuarios reales.
  • /clientes busca y administra clientes.
  • /clientes/:id muestra cuentas y gestiones reales.
  • /dashboard muestra indicadores reales por período.
  • /reportes filtra y exporta CSV.
  • /usuarios administra perfiles según rol.
  • /importaciones valida y carga CSV/TXT.

Las pantallas protegidas muestran datos reales del backend. Los formularios aplican campos obligatorios, correo, tipificaciones y reglas de compromiso.

9. PERSISTENCIA Y SEGURIDAD

MySQL contiene Usuario, Rol, Cliente, Cuenta, Telefono, Gestion, Pago, Promesa, TipificacionN1/N2, Carga y Auditoría. @Entity/@Table relacionan entidades con tablas; Repository JPA realiza el acceso y Service aplica transacciones.

Spring Security usa STATELESS y JWT. /api/auth/login, /api/publico/saludo y endpoints públicos están permitidos; /api/** requiere token. @PreAuthorize aplica permisos por rol.
